# Releases are cut from main by release-please and published to npm through trusted publishing

Work lands on `develop`, and `develop` is merged into `main` to release. On every push to `main`, release-please reads the Conventional Commit messages since the last tag and keeps a release PR open with the next semver version and CHANGELOG. Merging that PR tags `vX.Y.Z`, creates the GitHub release, publishes `@mintopia/cc-acp` from the same workflow, and opens a PR merging `main` back into `develop`. Publishing runs in the release-please workflow rather than on tag push because tags created with the workflow's own token do not trigger other workflows. npm authenticates the publish through OIDC trusted publishing, so the repository holds no npm token. Commit messages that are not Conventional Commits are left out of the version bump and CHANGELOG.
